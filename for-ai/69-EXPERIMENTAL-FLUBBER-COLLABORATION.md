# Experimental FLUBBER collaboration

This is the normative contract for Ground Control's reciprocal **Synch with Universe** and multi-source **Invite a FLUBBER** modes plus the Tauri settings WebView's compatible Party host/broadcaster roles. They extend the reviewed 12-byte coordinate transport; they are not chat, accounts, presence storage, experiment recording, physiology exchange, native remote-control authority, or a general networking API.

## Shared boundary

- Loading the page or desktop app constructs no VDO.Ninja client. Each mode starts only from its exact user action and stops on explicit stop, page/app close, or refresh.
- Universe and Party are mutually exclusive with one another and with every ordinary JSON/live send or receive role. They never enter portable settings, browser preferences, CSV, or Experiment state; Experiment start is blocked until collaboration stops.
- Public names, peer-IP visibility, third-party signaling/STUN/TURN, relay latency, and hosted-service availability carry the same disclosures as ordinary remote FLUBBER. Universe sends only bounded final/local-intent X/Y frames. Party guests may additionally provide the ordinary optional normalized viewport-placement frames and, only from the explicit QR guest controller, one bounded presentation token selecting Classic FLUBBER or an available checked-in portrait pack. The Party host returns a bounded aggregate containing public labels, X/Y, normalized scene positions, relative sizes, stale flags, participant appearance tokens, shared palette/base shape/amplitude/disorder/speed/opacity, and animation phase. No raw pointer trajectory, physiology, metric, timestamp, private participant identity, portable settings object, CSV row, or research state is added.
- Both modes reuse the locally vendored VDO.Ninja SDK and `flubber-remote.js` codec, partial-reliability channel, latest-state backpressure, stale hold, recovery hysteresis, diagnostics, and teardown. Ordinary X/Y and placement retain their 60 Hz cap and 100 ms heartbeat. Aggregate Party scenes are capped separately at 30 Hz with a 250 ms unchanged heartbeat and zero queued backlog. They add no backend, second Party connection, or WebSocket fallback.
- The QR guest's `affect-tracker-party-appearance` version-1 JSON envelope is capped at 256 UTF-8 bytes and contains only `flubber` or a syntactically bounded `photo-reference-v3`/`photo-synthetic-NN` token. The guest sends it through the already open broadcaster channel with bounded retries; the invited receiver alone records it for that stream, unknown or malformed values are ignored, and an unavailable local pack renders as Classic FLUBBER. The host echoes normalized appearance in the aggregate, which lets the guest repair a lost best-effort selection without an acknowledgement protocol or queued history.
- Browser Ground Control exposes **Display party QR** as a presentation-only invitation aid. The locally rendered code contains exactly the canonical public GitHub Pages `?party=join` URL—no secret, room ID, participant record, or study scope. Opening it immediately presents the disclosed **Name your FLUBBER** form but creates no VDO client. Only an explicit valid Join submission starts the existing ordinary `aft_flubber_` broadcaster, makes that public label discoverable, and returns the guest to the smartphone Affect controller with a **Party character** selector above the direct 2D grid. The selector offers Classic FLUBBER plus every available checked-in portrait pack and displays exactly one draggable representation at a time; its portrait labels and disclosure retain the neutral non-demographic evidence boundary. The host must independently open **Invite a FLUBBER** and select the source; neither QR display nor scan performs admission. The first valid returned aggregate containing the fresh guest stream ID is the automatic admission signal and keeps/restores that controller while rendering the shared scene. The page requests no camera/QR-scanner permission because scanning belongs to the phone's external camera app.

## Synch with Universe

- Universe is an explicit paired duplex exception intended for two people. Each named browser simultaneously advertises its own local control intent and discovers other Universe sources, but it excludes its own fresh random stream ID. Each browser selects only one incoming partner; as with every public unauthenticated room, unrelated listeners cannot be cryptographically excluded and must be treated as disclosed observers rather than trusted participants.
- Use public room `affect_tracker_universe_v1`, source prefix `aft_universe_`, label suffix `Universe FLUBBER`, and custom channel `flubberuniversev1`. Discovery never auto-selects: each person explicitly selects the other person's named source.
- Universe does not offer or consume ordinary placement packets. Its one shared displayed object retains local screen placement on each browser; only affect intent is combined.
- A browser is reciprocal-live only after it has received a valid partner coordinate and at least one listener is connected to its outgoing source. Receiving alone reports that it is waiting for the partner to choose back. The radar closes only on reciprocal-live, not on discovery, selection, connecting, or one-way receipt.
- Each browser preserves an independent locally smoothed full-scale intent pair. While reciprocal-live, the one displayed shared Flubber adds the two X intentions and the two Y intentions independently, then saturates each sum to `[-1,1]`; it never averages or halves either person's control. Either participant can therefore reach any axis extreme while the other is neutral, matching-direction inputs reach saturation sooner, and opposing inputs counteract one another. Because addition and saturation are commutative, both browsers converge without assigning a master. Stale holds the latest shared position; it never falls through to unrelated input.
- Universe transmission uses the existing Document Picture-in-Picture frame owner and renewable wake lock. Loss of that foreground helper is visible and recoverable with the same user-gesture restore action. Browser/OS scheduling cannot be overridden; reliable low latency still requires an active foreground frame owner.

## Invite a FLUBBER

- Party is a host-arranged shared scene, not affect co-control. The host's main Flubber and axes stay local. Each invited ordinary public `aft_flubber_` source is rendered as one separate labelled companion using only that guest's latest accepted X/Y: either its canonical Flubber or the exact available portrait pack selected by that QR guest. Flubber and portrait are mutually exclusive within the participant container on the phone, browser host, returned browser scene, and Tauri Party stage. The same container retains its bounded session-only position and can be dragged with pointer capture or moved with arrow keys without moving the host or another guest. When that source also provides normalized placement, the first placement anchors to the initial guest location without a jump; later source displacement moves only that guest by the same relative viewport delta. Any host-side guest drag or arrow move reanchors its independent offset. The browser host may wrap a Classic-FLUBBER first-live admission in its cellular birth transition; portrait admission renders directly because that transition is specifically Flubber geometry. The desktop host renders the accepted participant directly and does not claim the cellular presentation transition.
- Once at least one invited receiver exists, the host creates a fresh session-only Party ID and host participant ID. It assembles itself followed by every accepted guest in stable roster order and sends the same version-1 `affect-tracker-party-scene` JSON string through each guest receiver's existing `flubberxyv1` RTC data channel in reverse. The encoded UTF-8 payload is at most 8 KiB, contains 1–9 unique participants with exactly one host, clamps every numeric field, normalizes every appearance token to Classic FLUBBER or a bounded photo-pack ID, rejects malformed/older frames, and has no wall-clock timestamp. An absent appearance field decodes as Classic FLUBBER for backward compatibility. An invited ordinary broadcaster accepts a scene only when its own fresh stream ID appears in that roster, follows one host peer until that scene expires, and clears the scene after two receiver-local seconds without a valid update.
- Every connected browser or Tauri Party stage reconstructs the ordered roster, normalized placement, relative size, stale state, participant appearance, shared visual settings, and relayed animation phase. Canonical projection offsets are deterministically derived from each public session stream ID when Classic FLUBBER is selected; portraits use the selected checked-in atlas without affect tinting. The invited broadcaster's own displayed character adopts its returned Party position and relative size while continuing to send only its own ordinary X/Y/placement plus its explicit Party appearance token upstream. A guest never becomes Party host through this reply, cannot invite or arrange other Party characters through it, and does not receive another guest's direct connection; the host is the bounded relay authority.
- Party discovery never auto-selects. After the explicitly selected guest produces its first valid live frame, the radar closes automatically while the persistent roster remains visible. At that success boundary the local Flubber moves to viewport center. A Classic-FLUBBER guest enters a deterministic SVG cellular-growth cycle: `partyBudVectorGeometry` defines two sinusoidally perturbed compact scalar fields, the daughter begins as a small weighted deformation on the parent's membrane, grows while moving outward, and marching-squares extraction follows the `0.5` iso-surface as its shared saddle narrows from one closed contour into two. `morphPartyBirthContours` then arc-length resamples and cyclically aligns both extracted loops with the canonical renderer's live 192-point parent and stream-driven guest paths, interpolating every vertex until the temporary and ordinary boundaries coincide. Only then does the wrapper disappear. A portrait guest skips that Flubber-specific geometry and appears directly in the same final participant container; reduced-motion also skips movement. This one-shot presentation choice never changes coordinates or transport state. The main Invite action reopens discovery for another guest, so every guest still requires an explicit selection and an independent receiver connection. Invited sources may be individually removed; the persistent Stop action closes discovery and every guest receiver.
- A browser or desktop host supports at most eight invited guests. This is a deliberate CPU, WebRTC-peer, accessibility, and viewport bound—not a claim that VDO.Ninja globally limits the room. Duplicate invitations are idempotent. A stale guest remains visible at its held position and labelled state; it never takes over the local main axes.
- Smartphone layouts expose a Party-only local camera after a shared scene becomes active. One pointer on empty scene space pans, two pointers pinch about their centroid, the semantic range covers zoom `0.5`–`1.6`, and Reset returns to centered zoom `1`. Rendering projects every Party object through that camera and object drags use its inverse. Desktop layouts expose no Party camera, and the camera is never transmitted, persisted, recorded, or allowed to mutate the host-authored scene.
- Affect Tracker Desktop exposes two mutually exclusive explicit roles in the settings WebView. **Host Party and scan** projects its newest Rust snapshot into the host participant, invites ordinary public browser/desktop broadcasters, renders the authoritative aggregate locally, and fans the identical encoded scene to all guests. **Broadcast desktop Flubber** advertises Rust-authoritative current X/Y and a session placement so a browser host can invite it, then renders only newer returned scenes that contain its fresh stream ID. Returned coordinates are presentation-only and cannot invoke `set_target`, change settings/history/markers, or enter LSL. The reciprocal scene expires after two receiver-local seconds; the desktop source remains advertised for a fresh invitation. Stop and page teardown close both possible transports.
